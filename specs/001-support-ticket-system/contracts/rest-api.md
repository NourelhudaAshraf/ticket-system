# REST API Contract: Support Ticket System

**Feature**: [../spec.md](../spec.md) | **Data model**: [../data-model.md](../data-model.md)

The OpenAPI document generated by the `API` project (`/openapi/v1.json` in Development) is the
authoritative machine-readable contract and MUST match this file.

## Conventions

- Base path: `/api/v1`. JSON bodies use camelCase; enums are strings; dates are ISO 8601 UTC.
- **Auth**: cookie `ts_auth` (HttpOnly, Secure, SameSite=Strict). All endpoints require a signed-in
  user unless marked **Public**.
- **Pagination**: `page` (default 1), `pageSize` (default 20, max 100). Response:
  `{ items: T[], page, pageSize, totalCount }`.
- **No concurrency check**: ticket updates do not carry a version; the last save wins.
- **Errors**: one simple JSON shape `{ code, message }` (`DTOs/Common/ErrorResponse`). `message` is
  shown to people; `code` (below) is for client logic. Some errors add fields next to them:
  `errors: { field: [messages] }` (validation), `allowedNext: [status]` (`invalid_transition`).

| HTTP | `code` | When |
|------|--------|------|
| 400 | `validation_failed` | invalid input (field errors in `errors`) |
| 401 | `unauthenticated` | not signed in |
| 401 | `invalid_credentials` | wrong email/password |
| 403 | `forbidden` | signed in but not allowed (role or record level) |
| 403 | `email_not_verified` | customer submitting before verifying email |
| 404 | `not_found` | resource missing **or not visible to caller** |
| 409 | `email_taken` | registration/admin create with existing email |
| 409 | `name_taken` | duplicate category name |
| 422 | `invalid_transition` | status change not allowed; `extensions.allowedNext` |
| 422 | `ticket_read_only` | comment on Resolved/Closed ticket |
| 422 | `category_deleted` | category was soft-deleted |
| 422 | `agent_not_eligible` | user is not an agent, or the agent does not belong to the chosen category |
| 422 | `agent_is_default` | change would remove a category's default agent from that category or the Agent role |
| 500 | `server_error` | unexpected server error (details only in the server log) |

Tickets not visible to the caller return **404** (not 403) so their existence is not revealed.

## Shared shapes

Name fields (`categoryName`, `customerName`, `assignedAgentName`, `authorName`, `authorRole`) are
not stored; the server fills them by looking up the referenced ids.

```text
UserDto            { id, name, email, role, categoryIds[], emailVerified }
TicketSummaryDto   { id, title, status, priority, categoryId, categoryName,
                     customerName, assignedAgentId, assignedAgentName,
                     createdAt, updatedAt }
CommentDto         { id, authorId, authorName, authorRole, body, createdAt }
TicketPermissions  { canComment, canChangeStatus, allowedNextStatuses[], canEditPriority,
                     canReassign }
TicketDetailDto    = TicketSummaryDto + { description, relatedTicketId?,
                     comments[], resolvedAt?, closedAt?,
                     permissions: TicketPermissions }
CategoryDto        { id, name, defaultAgentId, defaultAgentName, agentCount }
```

## Auth — `/api/v1/auth`

| Method & path | Access | Body / query | Success | Notes |
|---------------|--------|--------------|---------|-------|
| `POST /register` | Public | `{ name, email, password }` | 201 `UserDto` | password ≥ 8 chars, letter + digit; queues verification email |
| `POST /verify-email` | Public | `{ userId, token }` | 204 | 400 `validation_failed` if token invalid/expired |
| `POST /resend-verification` | Public | `{ email }` | 202 | always 202 |
| `POST /login` | Public | `{ email, password }` | 200 `UserDto`, sets cookie | 401 per table |
| `POST /logout` | Signed in | — | 204 | |
| `GET /me` | Signed in | — | 200 `UserDto` | |
| `POST /forgot-password` | Public | `{ email }` | 202 | always 202; link valid 1 h |
| `POST /reset-password` | Public | `{ userId, token, newPassword }` | 204 | also used to accept an admin invitation |


## Tickets — `/api/v1/tickets`

| Method & path | Access | Body / query | Success |
|---------------|--------|--------------|---------|
| `GET /` | all roles | see list query below | 200 `Paged<TicketSummaryDto>` |
| `POST /` | Customer (verified) | `{ title, description, categoryId, priority?, relatedTicketId? }` | 201 `TicketDetailDto`, `Location` header |
| `GET /{id}` | can view | — | 200 `TicketDetailDto` |
| `POST /{id}/comments` | can comment | `{ body }` | 201 `CommentDto` |
| `POST /{id}/status` | can change status | `{ status }` | 200 `TicketDetailDto` |
| `PATCH /{id}` | can edit priority | `{ priority }` | 200 `TicketDetailDto` |
| `POST /{id}/assign` | assigned Agent, Admin | `{ agentId, categoryId }` — `categoryId` must be a non-deleted category the agent belongs to; the ticket's category becomes it | 200 `TicketDetailDto` |
**List query** (`GET /tickets`):

| Param | Values | Rules |
|-------|--------|-------|
| `scope` | `mine` (Customer default), `assigned` (Agent default), `category`, `all` (Admin default) | Customer: only `mine`. Agent: `assigned` or `category`. Admin: `all`. Other combinations → 403 |
| `categoryId` | id | with `scope=category`: must be one of the agent's categories, else 403; omitted = all their categories. With `scope=all` (Admin): optional filter to one category |
| `status`, `priority` | enum, repeatable | |
| `createdFrom`, `createdTo` | date | dashboard drill-down |
| `q` | string ≤ 100 | a 24-character ticket Id → exact Id match; otherwise text search on title + description (FR-013c) |
| `sort` | `createdAt` (default), `updatedAt`, `priority` | `dir` = `desc` (default) / `asc` |
| `page`, `pageSize` | int | |

Ticket create auto-assigns the ticket to the category's default agent. No emails are sent for
ticket events (ticket-update notifications removed 2026-11-04).

## Agents — `/api/v1/agents`

| Method & path | Access | Query | Success |
|---------------|--------|-------|---------|
| `GET /` | Agent, Admin | `categoryId?` | 200 `[{ id, name, categories: [{ id, name }] }]` — all agents with their non-deleted categories (reassign and default-agent pickers) |

## Categories — `/api/v1/categories`

| Method & path | Access | Body / query | Success |
|---------------|--------|--------------|---------|
| `GET /` | all roles | — | 200 `CategoryDto[]`, non-deleted only (customers: without agent fields) |
| `GET /{id}` | Admin | — | 200 `CategoryDto` |
| `POST /` | Admin | `{ name, defaultAgentId }` | 201 `CategoryDto` |
| `PUT /{id}` | Admin | `{ name, defaultAgentId }` | 200 `CategoryDto` |
| `DELETE /{id}` | Admin | — | 204; soft delete (`isDeleted = true`) |

`defaultAgentId` is required and must be an Agent; saving adds the category to that agent's
`categoryIds`. Names in ticket responses are looked up by id, so a rename shows everywhere at once. Deleted
categories return 404 here but their name still shows on existing tickets.

## Admin users — `/api/v1/admin/users`

| Method & path | Access | Body / query | Success |
|---------------|--------|--------------|---------|
| `GET /` | Admin | `role?`, `q?`, `page`, `pageSize` | 200 `Paged<UserDto>` |
| `GET /{id}` | Admin | — | 200 `UserDto` |
| `POST /` | Admin | `{ name, email, role, categoryIds[] }` | 201 `UserDto`; queues invitation email (72 h) |
| `PUT /{id}` | Admin | `{ name, role, categoryIds[] }` | 200 `UserDto` |

There is no delete or deactivate for users. Rules: Agents may have zero or more categories; admins cannot remove
their own Admin role; a category's default agent cannot lose the Agent role or leave that category
(`agent_is_default`).

## Dashboard — `/api/v1/admin/dashboard`

| Method & path | Access | Query | Success |
|---------------|--------|-------|---------|
| `GET /` | Admin | `createdFrom?`, `createdTo?` | 200 `{ total, byStatus: {Open, InProgress, Resolved, Closed}, byPriority: {Low, Medium, High, Urgent}, totalAgents, totalCustomers }` — user counts ignore the date range |

Drill-down: the client calls `GET /tickets?scope=all&status=…` (or `priority`) with
the same date range.
